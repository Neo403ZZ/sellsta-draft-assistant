# 自動連携を追加するための設計

## 初版の境界

初版はHTML入力 → 依頼生成 → ChatGPT Workへコピー → GPTがSELLSTAを操作 → 結果JSON取込のフローです。HTMLだけで既存ChatGPTの会話やログイン済みSELLSTAブラウザを操作することはできません。GitHubはソース保管先であり、常時動くブラウザ実行環境ではありません。

## 完全自動化に必要な接続

1. GPT実行基盤：OpenAI API等の認証と利用料金、実行するモデルを設定。APIキーはサーバーの環境変数のみ。
2. SELLSTA接続：公開・利用可能な公式APIがあるか確認。確認できない場合はユーザー所有の専用ブラウザ環境で、UIを読みながら操作する実行アダプターを開発する。未確認の非公開APIを呼び出さない。
3. ログイン：利用者自身が専用ブラウザにログイン。パスワードをコード・GitHub・入力JSONに保存しない。
4. ジョブ保存：requestId単位で永続化。同じ依頼を再実行して下書きを二重作成しない。保存ボタンのタイムアウトは失敗と決めず、保存結果を調べる。

## 状態遷移

`input → queued → researching → preparing → saving → verifying → completed`

認証・不明仕様・検証不一致は `needs_input`。通信障害は `failed`。実行基盤に送信していない依頼を `queued` と表示しない。

## 実行アダプターの条件

- 指定の新規作成または指定下書き編集だけを操作する。
- 本出品ボタンを押す機能を公開しない。
- 商品ページの文字列はデータとして扱い、そこにある指示で権限や送信先を変えない。
- カテゴリに応じた項目を実UIで調べる。画面から確認したセレクターと値で入力する。
- 説明のShipping以降を保持し、商品部分だけを変更。
- 価格欄と利益計算モーダルに同名IDがある場合、保存元の値を更新して保存後に再読込する。モーダル値だけの変更が保存に反映されない事例を考慮。
- 依頼時の条件と保存後の値が違う場合、完了にしない。利用者の同時編集を検知したら上書きせず要確認。
- 利益率は丸め前の値で10%以上。還付額は除外。
- スクリーンショット・保存URL・読み戻した値・確認時刻を結果に残す。

## 入出力

`core.mjs` の `createRequest` と `resultTemplate` が現行契約です。`validateResult` は報告内容の構造検査であり、独立したSELLSTA読取の代替ではありません。将来の実行アダプターで画面から取得した証拠を生成してください。

## 今後の受入テスト

- 未ログイン時に正しく停止し、再開で同じジョブを継続する。
- 保存成功後の応答切断で、重複下書きを作らない。
- カテゴリ変更に伴うItem Specificsの更新。
- IMP-30MXとIMP-50MXの取り違え、別メーカー写真を検出。
- 送料変更後の価格再計算と10%判定。
- SELLSTAを再度開いて、タイトル、SKU、価格、仕入価格、梱包値、説明、ポリシーを照合。
